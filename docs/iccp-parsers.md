# ICCP / TASE.2 parsers: Zeek and Wireshark

ICCP is TASE.2 (IEC 60870-6) carried over MMS on tcp/102. Two parsers read it, both MIT, both tested on the same pcaps
(`tests/pcaps/iccp`).

| Tool | Where | What it gives |
|---|---|---|
| Zeek (Spicy) package | `tools/zeek/iccp` | `mms.log` per MMS PDU, `iccp.log` per TASE.2 object operation, service `iccp` in `conn.log` |
| Wireshark / tshark post-dissector | `tools/wireshark/iccp.lua` | `iccp.*` fields, an "ICCP / TASE.2" tree, an `| ICCP ...` info-column suffix, over the built-in MMS dissector |

Details, columns and the list of unverified TASE.2 assumptions: `tools/zeek/iccp/README.md`.

## Wireshark / tshark

    tshark -r x.pcap -X lua_script:tools/wireshark/iccp.lua -Y iccp \
      -T fields -e iccp.op -e iccp.object -e iccp.class -e iccp.type -e iccp.value -e iccp.quality

For the GUI copy `iccp.lua` to `~/.local/lib/wireshark/plugins/`. Useful filters: `iccp`, `iccp.class == "transfer_set"`,
`iccp.ds_conditions contains "Integrity"`, `iccp.quality contains "SUSPECT"`, `iccp.bilateral_table_id == "BT_RANGE_01"`.
The capture must include the association (initiate) packets: without them Wireshark does not decode the data packets as
MMS and the post-dissector has nothing to read. Only connections that mention a TASE.2 object are tagged; plain IEC 61850
MMS is left alone. `make wireshark` runs it over the corpus and compares fields to `tests/pcaps/iccp/expected`.

## Zeek

    make zeek-iccp          # build and test in the ff-zeek container
    zeek -r x.pcap iccp.hlto tools/zeek/iccp/scripts

### In Malcolm

Malcolm 26.10 ships no MMS or ICCP package (its Zeek image pins ICSNPP packages, none for MMS). Three routes:
1. Custom package (fits this one, it needs a compiled analyzer): put the directory `tools/zeek/iccp` (it has a `zkg.meta`)
   in the Malcolm build context at `zeek/custom-pkg/ferrofire-iccp` (that is `/usr/local/zeek/custom-pkg` inside
   the image); `zeek_install_plugins.sh` installs everything there with `zkg install --nodeps --force --skiptests`. Rebuild
   the Zeek image.
2. Add a git URL for the package to `ZKG_GITHUB_URLS` in `zeek_install_plugins.sh`, rebuild the image.
3. `zeek/custom` (`@load custom`) loads scripts only, so it cannot add the compiled analyzer; it is enough if the
   analyzer is already installed and only `scripts/` changes.
`mms.log` and `iccp.log` are new streams: for them to be indexed, add a Logstash parse config and an OpenSearch field
mapping (Malcolm docs, "Parsing new Zeek logs"), otherwise Malcolm ignores them. Check the `ZEEK_DISABLE_SPICY_*` toggles
in `local.zeek` do not disable the package. Not yet tried in a running Malcolm.

### On the range

Mirror the range's tcp/102 traffic (control centre <-> ICCP server, ferrofire's ICCP server when ww-otj.46 lands) to the
Malcolm sensor or to a Zeek host. What to look at:
- `iccp.log` `class == "bilateral_table_id"` / `tase2_version` / `supported_features`: who talks to whom and under which
  bilateral table.
- Writes to `class == "data"` objects in a domain (device control points) and `start_transfer_set` operations.
- `report` rows: `ds_conditions` (why the report was sent), `quality` (SUSPECT, NOTVALID values), `timetag`.
- `mms.log` `rtt`, `result == "error"` and `error` for failed requests.
Stage 2 (open, bead ww-otj.49): capture ferrofire's own server, replay it as a regression pcap, and settle the unverified
TASE.2 assumptions.

## Test corpus

`tests/pcaps/iccp/`: `iec61850/*.pcap` (libiec61850 server and client examples, captured in a container by
`capture-iec61850.sh`; GPL code is built and run there only, the pcaps are data), `tase2_assoc.pcap`,
`tase2_report.pcap` (incl. a COTP-segmented report), `malformed.pcap`, `fuzz.pcap` (150 seeded mutants), generated by
`make_pcaps.py` (stdlib Python, raw bytes: `python3 -I make_pcaps.py <dir>`).

### Changes from the real captures (ww-otj.55, .62, .67)

- Both parsers were run over the Wireshark wiki `mms.pcap` and chaugan's `iccp_with_switchover_anon.pcap`
  (`tests/pcaps/iccp/fetch-real.sh`; never committed). They are structure-generic, so nothing about the shape of a value changed, but the
  synthetic `tase2_assoc.pcap` now carries what those captures carry: `TASE2_Version` {2000;8} and a **12-bit** `Supported_Features`
  (the old test string was 8 bits). `expected/tase2_assoc.tsv` and the Zeek baselines follow.
- A **refused read** (DataAccessError) of `TASE2_Version`, `Supported_Features` or `Bilateral_Table_ID` no longer replaces what the
  association learned: both parsers used to store the error code (`10`) as the value. The synthetic association refuses all three late on,
  and the goldens keep `{2000;8}` and the 12-bit string. (Found with telcon-tase2's test server, which serves none of them.)
- Zeek: `scripts/main.zeek` raises Zeek's log limits (`Log::default_max_*_container_elements` and `_string_bytes`). The defaults made
  `weird.log` rows (`log_container_field_truncated`, `log_string_field_truncated`) on the 7,972-frame capture and cut long name lists
  in `mms.log`.
- `make conformance PROTO=iccp` runs both parsers over the capture of the igs and telcon peers talking to ferrofire (the analyzer is built
  in the testpeers image and also attached to tcp/10102 and 10103, where the peers' servers listen) and over the real captures when they
  are present: 12-bit `Supported_Features`, `TASE2_Version` {1996;8} (mms.pcap) / {2000;8}, tshark 0 malformed, Zeek weird.log and
  reporter.log empty. See docs/testing.md.
